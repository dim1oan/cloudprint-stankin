1. **🖥️ Веб-панель администратора и диспетчера (`http://127.0.0.1:8000/`)**:

   - **Полноразмерный Header (Navbar)** с логотипом МГТУ СТАНКИН, вкладками сервиса, живым балансом студента, профилем и быстрым переходом в панель диспетчера;

## 2. Устраненные логические баги (Changelog)

### ✅ БАГ 1: Некорректная сумма компенсации и флоу работы с тикетами
- **Клиент (`client.html`):** Вкладка «Поддержка» содержит выпадающий список заказов студента (`supportOrderDropdown`). Студент выбирает конкретный заказ (`ORD-XXXXX`), видит его параметры (файл, страницы, стоимость) и регистрирует обращение строго по нему.
- **Бэкенд (`database.py`, `app.py`):** Внешний ключ `order_id` фиксируется в таблице `tickets`. При вызове эндпоинта `POST /api/tickets/{id}/compensate` диспетчер не вводит сумму вручную: сервер сам читает `orders.price_rub` и начисляет ровно 100% стоимости (например, 60.00 ₽) на бонусный счет студента.
- **Админка (`index.html`):** Кнопка диспетчера отображает **«Начислить компенсацию (100% — ХХ ₽)»** и выполняет начисление в один клик.

### ✅ БАГ 2: Пропажа старых заказов и история студента
- **Бэкенд (`database.py`, `app.py`):** Добавлен эндпоинт `GET /api/client/orders?user_id=1`, возвращающий массив всех заказов студента, отсортированный по дате `ORDER BY id DESC`.
- **Клиент (`client.html`):** Вкладка переименована в **«Мои заказы»** (`view-orders`). Рендерятся информативные карточки каждого заказа со статусами (`Готов к выдаче`, `Перенаправлен`, `Ошибка печати`, `Завершен`). Для активных заказов отображается пин-код и кнопка просмотра QR-кода; для завершенных заказов QR-код автоматически скрывается.

### ✅ Блокировка печати на неисправном терминале:
- При попытке оформить печать на терминале со статусом `Замятие E-04` или `Ожидает ТО` бэкенд возвращает **HTTP 400** с пояснением ошибки, а фронтенд блокирует кнопки отправки и оплаты.

## 3. Стек технологий

- **Backend:** Python 3.10+ (FastAPI, Uvicorn, SQLite3 `cloudprint.db`).
- **Telegram Bot:** aiogram 3.33+, qrcode, pypdf (запускается в едином асинхронном процессе с FastAPI).
- **Frontend:** HTML5, Tailwind CSS (через CDN), Font Awesome 6, Vanilla JavaScript (Fetch API, 3-секундный polling).
- **Сборка:** Не требует Node.js, Webpack или дополнительных инструментов сборки.

## 4. Быстрый запуск и синхронизация с Telegram

### Локальный запуск:
```powershell
cd "C:\Users\MSI\Desktop\CloudPrint Project"
python app.py
```

### Настройка Telegram-бота (единый процесс с сайтом):
1. Создайте бота через `@BotFather` в Telegram и скопируйте токен.
2. Вставьте его в файл `.env` (или укажите переменную окружения `BOT_TOKEN`):
   ```env
   BOT_TOKEN=123456789:ABCdefGhIJKlmNoPQRsTUVwxyZ
   ```
3. При старте `python app.py` сервер автоматически поднимет:
   - 🖥️ Веб-панель диспетчера: `http://127.0.0.1:8000`
   - 📱 Веб-клиент студента: `http://127.0.0.1:8000/client`
   - 🤖 Telegram-бот (в фоне, синхронизирован с сайтом)

> **Запуск на Render:** в настройках вашего веб-сервиса на Render перейдите в **«Environment»** и добавьте переменную `BOT_TOKEN` со значением вашего токена. Render сам запустит и сайт, и Telegram-бота!

### Двусторонняя синхронизация:
- **Диспетчер пишет на сайте:** ответ мгновенно сохраняется в чат веб-клиента и отправляется push-уведомлением студенту в Telegram-бот.
- **Студент пишет в Telegram:** сообщение моментально появляется в карточке тикета на панели диспетчера на сайте.
- **Диспетчер нажимает «Перевести на 2-й корпус»:** бот отправляет студенту новый цифровой пин-код и адрес резервного терминала.
- **Диспетчер одобряет 100% возврат:** бот уведомляет студента о зачислении бонусов на баланс.

Адреса в браузере:
- 🖥️ **Панель администратора и диспетчера:** 👉 **[http://127.0.0.1:8000](http://127.0.0.1:8000)**
- 📱 **Мобильный клиент студента:** 👉 **[http://127.0.0.1:8000/client](http://127.0.0.1:8000/client)**

Для запуска автоматических тестов:

## 5. Сценарий демонстрации на защите диплома / курсового проекта

Для наиболее наглядной демонстрации откройте два окна браузера рядом:
- **Слева:** интерфейс студента `http://127.0.0.1:8000/client`
- **Справа:** панель диспетчера `http://127.0.0.1:8000`

### Шаги демонстрации:
1. **Проверка защиты от печати на сломанном МФУ:**
   - На Шаге 1 выберите `Курсовой_проект_Детали_машин.pdf` (20 стр.).
   - На Шаге 2 выберите **Старый корпус (Терминал №1)**, который находится в статусе `Замятие E-04`.
   - Кнопка «Перейти к оплате» блокируется, появляется красное предупреждение.
   - Переключитесь на **Новый корпус (Терминал №2, Онлайн)** — кнопка становится активной.
2. **Оплата и создание заказа:**
   - Перейдите на Шаг 3 и нажмите **«Оплатить через СБП»**.
   - Пройдет симуляция оплаты, откроется экран выдачи с QR-кодом и цифровым номером (например, `542-819`).
3. **Просмотр истории заказов:**
   - Перейдите на вкладку **«Мои заказы»** внизу смартфона.
   - Заказ отображается вверху списка со статусом `Готов к выдаче` и кнопкой просмотра QR-кода. Старые заказы сохранены в истории.
4. **Фиксация аварии E-04:**
   - Перейдите на вкладку **«Поддержка»**.
   - В выпадающем списке выбран оформленный заказ (60.00 ₽, Новый корпус).
   - Нажмите красную кнопку **«Зажевало бумагу! (Ошибка E-04)»**.
   - Терминал №2 в панели администратора переходит в статус аварии, заказ получает статус `Ошибка печати`, открывается чат тикета.
5. **Действия диспетчера Цырулева А. А. (два сценария решения):**
   - **Сценарий А (Перевод печати без компенсации):**
     - Диспетчер нажимает **«🔄 Перевести на 2-й корпус (печать без компенсации)»**.
     - Заказ переносится на противоположный терминал (Старый корпус), генерируется новый 6-значный пин-код.
     - Компенсация не начисляется (баланс студента не изменяется), так как распечатка будет выдана в полном объеме по новому коду.
     - В окне студента статус заказа меняется на `Перенаправлен`, отображается новый терминал и новый код получения.
   - **Сценарий Б (Возврат средств при отказе от печати):**
     - Диспетчер нажимает **«💰 Вернуть средства (100% — 60.00 ₽)»**.
     - Бэкенд возвращает ровно 60.00 бонусов на баланс студента, а заказ помечается как `Отменен (Возврат)`.
